# 2.0 Diarization Probe

Status: API gate passed; first runtime gate failed and remains blocking.

## Verified

- Package: FluidAudio `0.15.5` (`Package.resolved` revision `19600a485baa4998812e4654b70d2bab8f2c9949`).
- Primary online candidate: `LSEENDDiarizer`.
- Model variant: `LSEENDVariant.dihard3`.
- Streaming step: `LSEENDStepSize.step100ms`.
- Model repository: `FluidInference/ls-eend-coreml`, optimized `dih3` bundle.
- Streaming API: `addAudio`, `process`, `processComplete`, and `finalizeSession`.
- Output: `DiarizerTimelineUpdate` with finalized and tentative `DiarizerSegment` values.
- Timeline values expose speaker index, start/end time, finality, and activity score.
- The API type-checks through `Tools/DiarizationProbe.swift` against the resolved
  build with the same macOS SDK used by the app.
- The probe is registered as the `DiarizationProbe` SwiftPM executable and accepts
  an optional WAV/CAF path, so it uses the same resolved FluidAudio build as the app.

## Adapter boundary

`SpeakerDiarizationAdapter` converts FluidAudio segments into local
`SpeakerDiarizationEvent` values. It keeps only finite, positive-duration
segments and emits opaque IDs such as `speaker-0`. It does not infer names or
claim that a system-audio speaker is the user.

## Runtime attempt

On 2026-08-15, a reproducible 13-second 16 kHz WAV fixture was generated locally
with two macOS speech voices (Daniel and Samantha) alternating in one file. The
probe completed successfully:

- model load: 8.637 s
- offline inference: 0.212 s
- reported speakers: 1
- finalized segments: speaker 0 at 0.0–0.6 s, 0.8–1.4 s, 1.6–6.8 s, and 7.0–12.3 s

This is useful performance evidence, but it is not an acceptable quality gate:
the fixture contained two intended voices and the model returned one speaker.
The fixture is synthetic and is not a substitute for an alternating-human-voice
recording, so the result does not prove the model is universally incapable of
separating speakers. It does prove that no speaker labels should be persisted or
shown in the shipped app yet.

## Not yet verified

- Two alternating voices have not been measured for diarization latency,
  speaker-count stability, or label churn.
- No diarization model is downloaded as part of the normal test suite.

The next gate is a real alternating-human-voice PCM fixture, followed by a
streaming probe run that records update latency, maximum speaker count, and
finalized-versus-tentative label stability. The persisted `Segment` model must
remain unchanged until that gate passes.

Example command after building the probe:

```text
swift run -c release DiarizationProbe /path/to/alternating-voices.wav
```
